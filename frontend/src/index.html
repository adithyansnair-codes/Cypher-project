DESIGN

                
Algorithms

                
How one frame becomes a prioritised, acknowledged incident.

            


            

        


        


            

                
How the AI finds objects

                ai/app/detector.py
                

                    The model looks at the image once. It returns a box, a class name
                    and a confidence score. It then removes repeated boxes drawn over
                    the same object.
                

                
    
                    
  • Classes: knife, pistol, person, fire, smoke, lying
    • 
                    
  • Trained on 18,642 images and checked on 2,656 separate images
    • 
                    
  • Weapon test score: mAP@50 0.890
    • 
                

            


            

                
How we stop false alarms

                ai/app/main.py
                

                    A single lucky-looking frame is not enough. We measured false pistol
                    alerts on a webcam and added three simple rules.
                

                
    
                    
  • Keep only the best box for each object type in a frame
    • 
                    
  • Require the same detection in eight frames in a row
    • 
                    
  • Wait 90 seconds before reporting the same class on the same camera again
    • 
                

            


            

                
How we tested the model

                ai/evidence/README.md
                

                    We tested the old and new models on the same 385 images that were
                    not used for training. This makes the comparison fair.
                

                
    
                    
  • Old weapon score: 0.589
    • 
                    
  • New weapon score: 0.890
    • 
                    
  • Knife recall improved from 0.345 to 0.843
    • 
                    
  • All six classes together: 0.744 mAP@50
    • 
                

            


            

                
Who decides how serious it is

                IncidentService.deriveSeverity
                

                    The AI only says what it saw. The CYPHER backend decides whether
                    the event is low, medium, high or critical.
                

                
    
                    
  • Weapons and fire: always CRITICAL
    • 
                    
  • Smoke, fall and lying: HIGH at 85% or above, otherwise MEDIUM
    • 
                    
  • Other classes use confidence thresholds
    • 
                

            


            

                
What our team built

                data · rules · backend · cloud
                

                    YOLO is an existing detector architecture. Our work was making it
                    useful inside one complete incident-management product.
                

                
    
                    
  • Combined five datasets and fixed their label formats
    • 
                    
  • Built the webcam, image and live-video detection flow
    • 
                    
  • Added false-alarm rules, severity rules and incident saving
    • 
                    
  • Connected the AI to the dashboard, database, audit and AWS deployment
    • 
                

            


            

                
How incidents are saved

                create_incident_with_alert()
                

                    CYPHER saves the incident and its alert together. If one save fails,
                    both are cancelled, so the dashboard cannot contain half an incident.
                

            


            

                
How login is protected

                JwtService · JwtAuthenticationFilter
                
    
                    
  • Passwords are stored as secure one-way hashes
    • 
                    
  • After login, a signed token proves who the user is
    • 
                    
  • Expired or invalid tokens cannot access private data
    • 
                

            


            

                
How the dashboard updates live

                IncidentSocketHandler
                

                    After a new incident is saved, CYPHER pushes it to every open
                    dashboard. If the live connection drops, the page reconnects and
                    periodically refreshes instead.
                

            


            

                
How permissions and history work

                SecurityConfig · trg_incident_changes
                

                    Only allowed roles can acknowledge, resolve or delete incidents.
                    The database automatically records changes in the audit trail.
                

            


            

                
How reports are created

                reporting/ (C#)
                

                    CYPHER reads the saved incidents and creates CSV, Excel or PDF
                    reports. The browser downloads them using the same secure login.
